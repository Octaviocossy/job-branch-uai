## Goal

## Context

**Current state:**
- The monorepo has three apps: `apps/web` (Next.js frontend), `apps/api` (NestJS backend), and
  `apps/v0-prototype` (the original v0 visual prototype, package name `my-project`).
- `apps/v0-prototype/` is a git-tracked workspace member: **101 tracked files** plus untracked
  build artifacts on disk (`.next/`, `node_modules/`, `.turbo/`, and its own nested
  `pnpm-lock.yaml`). One tracked file is currently modified (`next-env.d.ts`, shows `M` in
  `git status`).
- `SPEC.md` is a tracked 332-line root file — the original academic functional spec.
- The prototype is a **leaf**: nothing imports its package (`my-project`). `apps/web` and
  `apps/api` do not depend on it. `docker-compose.yml`, root `README.md`, and CI are already
  clean (they only mention `web`/`api`). So the app can be removed without touching any runtime
  code.

**What prompted this:** user request — "remove the prototype project from `apps/` and the
`SPEC.md` file."

## Architecture Decisions

- **Leave the completed historical plan untouched.**
  `.agents/plans/2026-07-13-epic-jobbranch-fullstack.md` references the prototype and `SPEC.md` in
  prose (e.g. "implement the v0 visual prototype (`apps/v0-prototype/`)", "Follow `SPEC.md`"). It
  is a **dated, completed** archival record of what was built; rewriting it would misrepresent the
  history it documents. Broken references inside a historical plan are acceptable — they describe
  the state at the time. (Flagged in Open Questions in case the user disagrees.)
- **Remove file-path links, keep conceptual vocabulary attributions.** In the glossary, only the
  `SPEC.md`/`apps/v0-prototype/lib/data.ts` **file links** and `SPEC §N` citations that read as
  file references are removed. Prose that attributes Spanish terms to "the SPEC"/"the deliverable"
  stays, because it explains term provenance without creating a broken link.
- **Redirect docs to the glossary, not to a deleted file.** `docs/DOCUMENTACION.md` is repointed
  at `.agents/ubiquitous-language.md` (the surviving canonical domain source) rather than simply
  dropping the context.
- **Delete via `git rm -rf` + `rm -rf`** rather than a plain `rm`, so the deletion is staged in
  git in one step and untracked build artifacts are also cleared.
- **No config changes required.** `pnpm-workspace.yaml` (glob), `turbo.json` (no path list),
  `biome.json` (global `**` include; no `v0-prototype` override), `docker-compose.yml`, root
  `README.md`, and CI contain no prototype references — verified by grep. Only the lockfile
  changes, and only via `pnpm install`.
